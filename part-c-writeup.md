# Зарплатный конвейер и ответы на вопросы сотрудников — краткое описание решения

## Как это работает

Две связанные автоматизации на n8n поверх Google-таблиц.

**Часть 1 — расчёт зарплаты.** Данные (сотрудники, активность, корректировки, ручной расчёт HR) считываются из таблицы, и детерминированный «движок» на Apps Script считает выплаты по фиксированным правилам: прориоризация по рабочим дням, курсы валют, налоги, комиссии платёжных систем. Результат сверяется с ручным расчётом HR: для каждого расхождения система объясняет причину (например, «ручной расчёт не учёл досрочную выплату»). Любые подозрительные входные данные не исправляются молча, а помечаются флагом с причиной. Итог — таблица с подсветкой и полный отчёт о расхождениях.

**Часть 2 — обработка обращений сотрудников.** Каждое обращение проходит три фильтра: (1) автоматическая проверка на попытки манипуляции/injection до передачи в нейросеть, (2) нейросеть извлекает из текста структуру (категория, суммы, часы, даты) с жёсткой схемой и валидацией ответа, (3) маршрут определяется фиксированными правилами: вопрос о своих деньгах при расхождении с ручным расчётом → Finance; смена способа выплат → HR; вопрос о чужой зарплате → вежливый автоматический отказ; что не прошло проверку — стандартный ответ. Затем нейросеть пишет черновик тёплого ответа сотруднику — по единому промпту, без сумм, без внутренних деталей, только по имени; черновик проходит контроль (запрещены цифры и внутренние термины), иначе подставляется шаблон.

**Где фиксированные правила, а где LLM — и почему.** Все деньги, налоги и маршрутизация — только код: это должно быть воспроизводимо, проверяемо и не может «галлюцинировать». LLM используется лишь там, где нужен язык: понять свободный текст обращения и написать человеческий ответ. При этом LLM никогда не видит исходный текст обращения (защита от манипуляций), не получает персональные данные (только имя и цель ответа) и не может изменить ни одну цифру.

## Продакшн в Kodland

- **Хостинг:** n8n (self-hosted или cloud) за SSO; для сотрудников — простой внутренний портал на Netlify (форма обращения + статус), общающийся с n8n через вебхуки.
- **Доступ к данным:** для пилота — Google Sheets с ограниченным доступом; в продакшне — БД (Postgres) с правами по ролям, ключ сотрудника — Slack ID.
- **Персональные данные и секреты:** минимум данных в промптах (уже реализовано), ключи и токены — в хранилище секретов n8n, не в коде; для LLM — модель с гарантией residency или self-hosted; ответы другим сотрудникам о чужих выплатах заблокированы архитектурно.
- **Логирование:** история исполнений n8n + результирующие таблицы = полный аудит-трейл; добавить алерты об ошибках (Slack/email) и политику хранения логов.
- **Лимиты затрат LLM:** по телеметрии n8n — ~1200 токенов на обращение (≈900 извлечение + ≈300 черновик ответа); ограничения бюджета на день/месяц на уровне воркфлоу, при превышении — автоматический откат на шаблонные ответы.

## Тестирование с HR перед запуском

Теневой режим 1–2 цикла: система работает параллельно с ручным процессом, HR сравнивает результаты (сверка с ручным расчётом уже встроена). Затем UAT на ~50 исторических обращениях, включая граничные случаи (попытки манипуляции, вопросы о чужой зарплате). Метрики: доля совпадений с ручным расчётом, корректность маршрутизации, доля правок HR в черновиках.

**Первые вопросы HR:**
1. Кто Finance и HR ответственны за обработку обращений (кому перенаправлять сообщения, не обработанные auto reply)?
2. Какие формулировки допустимы в ответах сотрудникам (тон, можно ли упоминать расчеты, финансовые детали)?
3. Нужно ли репортить сотрудников, которые пытаются сломать систему или пытаются выяснить чужие данные?
4. Какой пользовательский интерфейс привычнее - отдельный дашборд / кастомные кнопки в таблице / бот в слаке / свой вариант?
5. Какие ошибки ручного расчёта встречались чаще всего — чтобы приоритизировать проверки?

## Что не закончено и что дальше

Источник обращений сейчас вшит в воркфлоу (нужна интеграция со Slack/email); черновики не отправляются автоматически — нет шага подтверждения человеком перед отправкой; тестов и мониторинга.
Дальше: приём обращений из Slack, кнопка «подтвердить ответ» для HR, перенос данных в БД, панель затрат LLM и поддержка нескольких периодов, алерты.
